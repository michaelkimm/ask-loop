$ARGUMENTS 파일의 요구사항을 구체화해줘.

## 워크플로우

### 1. 요구사항 분석
- 파일 읽고 언급된 기술/개념 식별
- 불명확한 부분, 결정이 필요한 부분 파악

### 2. MCP 조사 (서브에이전트로 위임)
Task 도구(subagent_type="general-purpose")로 조사 위임:
- 프롬프트: "다음 기술들을 조사해줘: {기술 목록}. Context7로 공식 문서, Grep.app으로 구현 패턴, Exa로 최신 트렌드 확인. 각 기술의 트레이드오프와 베스트 프랙티스를 요약해서 반환해줘. 반드시 출처 URL과 참고한 원문을 함께 반환해줘."
- 서브에이전트가 조사 후 요약만 반환 → 메인 컨텍스트 절약

### 2-1. 리서치 결과 저장
원본 파일과 같은 디렉토리에 저장:
- `{파일명}-research_summary.md`: 요약
- `{파일명}-research_detail.md`: 상세

예: `/refine docs/auth.md` → `docs/auth-research_summary.md`, `docs/auth-research_detail.md`

**요약 파일 형식**:
```markdown
# 리서치 요약: {원본 파일명}

## 조사 대상 기술
- {기술1}
- {기술2}

## 핵심 트레이드오프
| 기술 | 장점 | 단점 | 적합한 상황 |
|------|------|------|-------------|

## 추천 사항
{베스트 프랙티스 요약}

## 출처
[1] {URL}
```

**상세 파일 형식**:
```markdown
# 리서치 상세: {원본 파일명}

## {기술1}

### 공식 문서 (Context7)
{조사 내용}
> 원문: "{인용}"
> 출처: {URL}

### 구현 패턴 (Grep.app)
{코드 예시}
> 출처: {URL}

### 최신 트렌드 (Exa)
{트렌드 내용}
> 출처: {URL}
```

### 3. 조사 기반 질문
- AskUserQuestion으로 요구사항 구체화 질문
- 각 옵션에 조사 결과 반영 (트레이드오프 설명)
- **모든 질문에 "팀 내부 조사 후 결정" 옵션 포함** → 이 답변은 "사전 조사 필요" 항목으로 분류

### 4. 답변 반영
- 사용자 답변을 요구사항에 통합
- 파일에 덮어쓰기

## 인용 규칙 (필수)

**MCP로 조사한 내용만 출처 표시. 추론이나 출처 없는 내용은 표시하지 않음.**

본문:
```
JWT는 stateless라서 서버 확장이 용이하다[1]. 토큰 만료 시간은 보통 15분~1시간을 권장한다[1].
```

참고 자료:
```
[1] https://auth0.com/blog/jwt-handbook/, "For access tokens, 15 minutes to 1 hour is common. JWTs are stateless, making horizontal scaling straightforward."
```

```markdown
|------|----------|-------------|

| 결정 사항 | 선행 조사 | 옵션 |
|----------|----------|------|

## 참고 자료
[1] {URL}, {참고한 원문}
[2] {URL}, {참고한 원문}
```
